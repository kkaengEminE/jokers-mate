# 11 · 데이터 모델

## 판 상태

| 타입 | 내용 |
|---|---|
| Card | 고유 실물 id, rank, suit. 조커는 J1/J2 |
| Game | version, 판 id, 판 번호, phase, economy(경제 버전), SAN 수순, 칸→Card 배정, 잡힌 카드, banks, committed, 체스·포커 결과, 선택 패, 베팅, 정산, 업적 |
| Betting | 차례, 행동 여부, 직전 레이즈 폭, 레이즈 잠금, 종료, 폴드, 행동 로그 |
| Settlement | 최종 잔액, 미매칭 반환, 체스 배당, 포커 배당, 팟 |
| RecordEntry | 날짜·판·결과·경제 버전·PGN·공개 카드·업적·정산 |

- 색 `w`는 플레이어, `b`는 컴퓨터다.
- `banks`는 참가금 이전 잔액, `committed`는 참가금(개인 체스 대응몫20 포함)을 포함한 누적 투입액이다. 진행 중 금고는 `banks − committed`.
- 카드 배정은 생존 칸만 보유하고, 잡히면 제거한다.
- chess.js 상태는 SAN 수순을 재생해 재구성하므로 반복 이력을 잃지 않는다.
- `economy`: 현재 규칙은 `r4`. 이전 버전 값(`r3`, `split-15-5`, 값 없음)으로 시작한 판은 그 규칙으로 끝낸다.

## 캠페인·프로필 상태

| 구분 | 필드 |
|---|---|
| 이야기 | 이야기 id, 계약(규칙) 버전, 현재 상대 id, 프롤로그 시청 여부 |
| 판 경계 | 판 id, phase, 결과 확정(resultCommitted), 결과 확인(resultAcknowledged), 미완료 판 표시 |
| 엔딩 | 엔딩 시청 완료(endingViewed) |
| 영구 프로필 | 칭호, 초상, 업적, 기록 — 새 게임과 무관하게 유지 |

결과 계산·잔액 변경·미완료 표시 해제는 하나의 저장 단위로 처리한다. 다시 열기·탭 중복·이중 클릭으로 중복 정산하지 않는다. 저장에 실패하면 새 판 입장을 막는다. 두 탭에서 동시에 열면 한 탭만 활성화한다.

## 복구 검증

버전, 수순 합법성, 생존 칸과 카드 수, 32장 고유 카드, 정규 덱 정체, 정수 원장과 합계, 생존 패 자격, 상태별 결과 유무, 체스 종료 결과, 해당 경제 버전 정산식의 일치를 검사한다. 깨진 상태는 부분 복구하지 않는다. 원본을 복구용 키에 보관할 수 있으면 보관하고 새 게임을 시작한다.

## 보존 키

브라우저 저장 키는 이름 변경과 무관하게 기존 값을 유지해 저장 데이터를 보존한다. 도메인이 바뀌면 브라우저 저장소가 자동으로 옮겨지지 않으므로 내보내기/가져오기 이전 방법이 필요하다.

## 범위 밖

싱글플레이 전용 구조다. 서버 권위 판정, 치트 방지, 클라우드 저장은 범위 밖이다.

## 현재 구현 대응 (2026-10-23)
`journey.opponent`와 `journey.screen`으로 상대 및 프롤로그/엔딩/실패/완료를 저장한다. 최종 `phase=result`와 `settlement`를 한 스냅샷에 저장해 확정 표시로 사용한다. `abandoned`는 도주 정산이다. 별도 resultAcknowledged 필드는 아직 없으며 화면 확인 전까지 결과를 취소하지 않는다. 칭호는 별도 영구 키에 저장한다. 상세 시청 진도·최종 초상·크레딧은 후속 제작이다.
