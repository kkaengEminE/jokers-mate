# 모바일 게임성·출시 준비 검토

2026-11-04. `main`의 일기토 구현에 세 요소 조합식·진영·KO 연출·모바일 사용성 수정을 적용한 소스를 대상으로 검토했다. 자동 검사, Chromium 터치 에뮬레이션, 화면 측정과 육안 검토를 함께 사용했다. 실물 iPhone·Android에서의 시험 또는 앱스토어 심사 결과는 아니다.

## 판정

**웹 테스트 배포 가능 / 시판 모바일 앱 출시 준비는 미완료.** 체스→카드 선택→포커→정산의 핵심 흐름과 설정의 일기토는 작동한다. 정원과 체카드의 미술 방향도 일관된다. 다만 처음 배우는 사람의 안내, 실기기 조작감, 일기토의 본편 연결, 전투 모션과 장기 밸런스를 더 다듬어야 한다.

| 평가 항목 | 현재 수준 | 판단 근거 |
|---|---|---|
| 기본 진행·정산 | 테스트 배포 가능 | 선택·순서 교환·베팅 확정·쇼다운·정산을 브라우저에서 확인. 원장·규칙은 자동 테스트로 보완 |
| 모바일 조작·배치 | 주요 문제 수정, 실기기 확인 필요 | 작은 조작부 확대, 3개 화면 크기에서 조작부 노출·동시 터치 확인 |
| 기물 식별·승패 피드백 | 개선됨, 모션 추가 필요 | 반대 진영 강제, 기술의 실제 차이, 결과창 이전의 3초 KO 연출. 연결 프레임과 별도 승리 모션은 부족 |
| 첫 플레이 이해 | 보완 필요 | 도움말은 있으나 체스와 포커, 금화 배치, 상중하 방어를 직접 가르치는 단계별 안내가 없음 |
| 장기 게임성·밸런스 | 추가 플레이 검증 필요 | 324개 조합의 계산은 검증했지만 조합별 승률과 캠페인 경제의 적절한 플레이 시간은 검증하지 않음 |
| 모바일 앱 배포 준비 | 미완료 | 네이티브 패키지·실기기 배포 시험·스토어 제출 준비 완료 근거가 없음 |

## 적용한 기준

- 터치 조작은 Apple의 44×44pt, Android의 48×48dp 권고를 참고했다. 웹에서는 논리적 크기인 CSS px로 측정하며 단위가 물리적으로 항상 같다는 뜻은 아니다. 반복 조작은 가능하면 48px 이상, 보조 버튼은 최소 44px을 목표로 한다.
- WCAG 2.2 AA의 타깃 크기 기준은 원칙적으로 24×24 CSS px이며 간격·동등한 조작·필수 배치 등의 예외가 있다. 44/48px 목표와 이 기준을 혼동하지 않는다. 모든 체스판 칸을 48px로 만들었다고 판단하지 않는다.
- 핵심 설명은 14~16px, 보조 수치는 12px 이상을 프로젝트의 가독성 목표로 삼았다. WCAG가 모든 글자에 이 최소 글꼴 크기를 요구하는 것은 아니다.
- 글자 대비 목표는 일반 4.5:1, 큰 글자 3:1이다. 그림 위의 모든 색 조합과 상태를 측정하지 않았으므로 전체 대비·접근성 준수를 인증하지 않는다.
- 320×568, 390×844 세로와 844×390 가로에서 화면 밖으로 나가는 주요 조작부, 가로 넘침, 모달 복귀, 카드 식별, 동시 터치를 확인했다.

참고: [Apple Buttons](https://developer.apple.com/design/human-interface-guidelines/buttons), [Android Touch target size](https://support.google.com/accessibility/android/answer/7101858), [WCAG Target Size Minimum](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html), [WCAG Contrast Minimum](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html).

## 이번에 수정한 문제

| 문제 | 원인과 수정 | 확인 |
|---|---|---|
| 일기토 양쪽 기물이 같은 진영처럼 보임 | 스프라이트 원본의 밝은/어두운 의상을 그대로 사용하고 진영 입력이 없었다. 내 진영을 하나만 저장하고 상대는 항상 반대로 계산. 선택 화면·경기장 모두 명시적 진영 색과 글자를 사용 | 6기물 각각에 백/흑 배정, 반대편 색 확인. 실제 경기 화면에서도 확인 |
| 기물 선택이 기술에 영향을 주지 않음 | 이전 조합식에서 역할은 외형 전용이었다. 기물별 기본기, 연계 계수·마무리 높이·동작, 이동 속도를 추가 | 퀸 ♠10은 하단 기본기 4.75, 킹 ♠10은 중단 6.65. 하단 방어 상대의 실제 체력 결과도 다름 |
| KO 순간 패배 포즈가 가려짐 | 종료 즉시 경기장을 가리는 배너가 나타났다. 피격 정지→느린 밀림→주저앉기를 먼저 보여 주고 3초 후 결과창 표시 | 400ms에 피격, 1.2초에 주저앉기, 1.9초까지 딤 없음. 결과 노출은 약 3초 뒤 |
| 일기토의 작은 방향·정지 버튼 | 모바일에서 방향 폭 38~42px, 정지 높이 24~28px이었다. 방향 48×56px, 정지 48×48px, 세로 화면 공격 버튼 높이 64px로 확대 | 3개 화면 크기와 이동+공격 / 아래+방어 동시 터치 확인 |
| 작은 수치·안내와 터치 환경의 키보드 표기 | 체력 글씨 8~9px 등을 확대. 체력·필살기 수치 12px, 선택 글자 16px, 설명 크기 보완. 터치에서는 키보드 배지 생략 | 좁은 화면에서 수치·선택·조작을 읽을 수 있는지 검토 |
| 본편 닫기·기록·잡은 카드 조작부가 작음 | 보조 버튼과 요약 영역을 최소 44px로 확대, 안내 크기 보완 | 베팅 3개 크기에서 주요 버튼이 화면 안에 있고 실제 동작함 |
| 새 게임 확인에 브라우저 기본 confirm 사용 | 게임 안의 확인 모달로 교체. 취소·닫기·Esc는 이전 메뉴로 복귀 | 취소 후 진행 중 원장 보존, 기본 브라우저 대화상자 발생 0건 |
| 본편 중 일기토를 열고 앱 전환하면 대결이 사라짐 | 본편의 탭 숨김 처리에서 열린 모달을 메뉴로 덮어썼다. 현재 모달·승격 선택을 보존 | 일기토는 정지 상태로 남고 본편 저장 데이터도 유지 |
| 설정을 다시 열 때 선호가 초기화됨 | 힌트·모션과 일기토 진영·효과음 저장 | 선택 복원·재대결·설정 왕복 확인 |

기술 수치와 조합 규칙은 [조합식 v2](36_CARD_DUEL_FORMULA_V2.md), 사용법과 구현 범위는 [테스트 모드 안내](35_CARD_DUEL_TEST_MODE.md)에 별도로 기록했다.

후반 카드 선택·베팅·정산 화면은 개발 fixture를 사용했다. 한 번의 실제 체스 대국으로 캠페인 전체를 완주한 시험이 아니다. 단위 테스트의 324개 조합 순회도 324회의 사람 플레이와 다르다.

배포용 하위 경로의 프로덕션 빌드도 루프백에서 따로 열어 확인했다. Pages 배포 상태는 이 커밋의 GitHub Actions 결과로 확인한다. 공개 Pages 주소 직접 접속은 현재 네트워크 정책에서 HTTP 403이므로 로컬 검증을 공개 서버 접속 성공으로 보고하지 않는다. Google Fonts 요청 역시 정책상 연결되지 않아 화면 검토는 대체 글꼴로 진행했다. 네트워크 정책은 변경하지 않는다.

## 출시 전 남은 작업

1. **실제 iOS/Android 검증:** Safari/Chrome의 주소창, 노치·홈 인디케이터, 시스템 글자 확대, 화면 회전, 앱 전환, 오디오 중단, 저사양 성능을 시험한다. 현재 시험은 Chromium 에뮬레이션이다.
2. **첫 플레이 안내:** 첫 판에서 체스 생존 카드가 포커로 넘어가는 이유, 금화는 준비 후 확정해야 하는 점, 동률 패 비교를 행동과 함께 가르친다. 일기토는 이동→기본기→서서 방어→앉아 방어를 짧게 연습하게 한다.
3. **본편 일기토 연결:** 정산 후 보유 카드 선택→신청→상대 수락/거절→대결→본편 복귀를 구현한다. 현재 입구는 요청대로 설정의 테스트 버튼이다.
4. **그림과 타격감:** 현행 8개 핵심 포즈에 연결 프레임, 찌르기·팔꿈치·쓸기의 개별 동작, 높이별 피격, 별도 승리 모션을 더한다. 특히 짧은 화면에서 기물의 자세·팔다리·문양이 겹치지 않는지 실기기로 확인한다.
5. **조합·AI·경제 플레이테스트:** 기물별 기본기가 선택할 가치가 있는지, 특정 사거리/콤보의 반복이 우세한지, 조커와 312개 일반 조합의 편차, 21억G 황제전까지 필요한 시간과 파산 난도를 검증한다. 수치 상한 검사는 공정한 밸런스의 증명이 아니다.
6. **중단 복원:** 진행 중 일기토와 확정 전 카드 선택은 새로고침 후 완전히 복원되지 않는다. 모바일에서 프로세스가 종료될 때 어느 단계까지 복구할지 정하고 저장한다.
7. **앱 패키징·배포 준비:** iOS/Android 패키지, 서명·실기기 설치, 앱 아이콘·시작 화면, 개인정보/연령 등급/스토어 설명을 준비한다. 저장소에는 현재 네이티브 프로젝트와 서비스 워커가 없다. PWA는 선택 가능한 웹 배포 방식이며 네이티브 앱 제출의 필수 조건은 아니다.

추가 가독성 과제도 남아 있다. 작은 체스판의 칸은 화면 폭 때문에 44px보다 작을 수 있고 숫자 표기도 작다. 선택 기물의 정보 영역은 보완했지만 확대 기능·대체 선택 방식을 검토해야 한다. 일부 장식 문구·기술 보조 표시는 8~11px이며 전체 글자가 12px 이상인 것은 아니다. 320px의 짧은 화면에서 본편은 전신 체카드 대신 간략 카드 면을 사용하므로, 큰 화면과 같은 미술 밀도를 기대하면 차이가 느껴진다. 외부 웹폰트가 차단돼도 대체 글꼴로 동작하지만, 상용 앱에서는 글꼴을 함께 제공하거나 실제 사용 글꼴별 배치를 검증해야 한다.

출시 판단을 올리는 다음 관문은 **실기기 주요 흐름 통과 + 첫 플레이 안내 + 본편 일기토 연결 + 모션·밸런스 플레이테스트**다.
