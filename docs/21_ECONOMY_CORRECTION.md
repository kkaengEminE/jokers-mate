# 정산 기준 정정 및 전체 사례 — R3

2026-10-22. 최신 사용자 정정: “나는 계속 내가 내는 비율, 받는 비율로 얘기하고 있는데 … 합칠거면 서로 금액을 합친거로 계산해야지.”

## 오류 기록
R1: 각자15/5, 체스승자30·포커승자10. 체스무승부에는15씩 돌려주도록 구현했으나 ‘무승부면 중앙에 남는다’ 지시와 불일치.
R2: 총40 중 체스승자에게15만 배당, 포커승자25. **개인별 배분15를 양측 합산 배당15로 잘못 해석한 assistant 오류.** 문서20의 해당 계산은 폐기한다. 금화 합계가 보존된다는 검증은 사용자 규칙에 맞다는 증거가 아니었다.
R3: 개인별 체스15/포커5를 양측에 똑같이 적용. 결정적 체스 결과이면 체스30/포커10. 체스무승부이면 별도 반환 없이40 모두 포커에 남긴다. 아래 모든 표는 이 기준이며 숨은 비율 변경은 없다. 실제 코드는 아직R1이다.

## 1. 납부와 합산을 분리
| 납부자 | 체스 몫 | 포커 몫 | 총 납부 |
|---|---:|---:|---:|
|나|15|5|20|
|상대|15|5|20|
|합계|30|10|40|

체스 승자는 내 체스몫15와 상대 체스몫15를 함께 받는다. 포커 승자는 내 포커몫5와 상대 포커몫5를 함께 받는다. 두 게임을 모두 이긴 사람만40 전부 수령한다. 체스 종료 시에는 받을 몫만 확정하고 실제 지급은 포커 종료 뒤 한 번이다. 참가금과 순이익은 다르다.

**이 규칙에서 체스승/포커폴드는30 수령·순이익10이다.** 따라서 체스만 계속 이기고 포커를 포기해도 수익이 남는다. 개인별15/5 비율을 유지하면서 그 전략의 순손익을음수로 만드는 것은 불가능하다. 그 문제를 막으려고 비율이나 배당 의미를 몰래 바꾸지 않는다. 변경을 원하면 별도 승인 사항이다.

## 4. 일반 정산식
B_i=시작 잔액, C_i=참가20 포함 누적투입,20≤C_i≤B_i.
m=min(C_w,C_b), 미매칭반환 R_i=C_i-m.
체스승자 있음: A_승=30,A_패=0, P=2m-30.
체스무: A_w=A_b=0, P=2m.
포커승자 W_i=P, 패자W_i=0.
F_i=B_i-C_i+R_i+A_i+W_i.

합계 F_w+F_b=B_w+B_b. **2000으로 하드코딩하지 않는다.** 황제전도 같은 식. 확정된 체스30은 해당 판 추가 베팅에 재사용하지 않는다. 베팅 가능한 금고는B_i-C_i. 최종20보호 보정 없음.

## 6. 도주 패배 — 일반 폴드와 다른 사건
사용자 지시: 체스/포커 진행중 종료하면 도주패배. 일반 폴드는 합법행동으로 체스몫을 유지한다. 도주는 이번 판 전체 패배로 제안 명세화: 지금까지 납부한 내 C_나 전액을 상대에게 넘기고, 상대가 납부한 C_상대는 상대에게 돌려준다. 내 미납부 금고는 유지. 체스몫30도 도주자는 못 받는다. 내최종=B_나-C_나, 상대최종=B_상대+C_나. 초과반환으로 도주손실을 회피하지 않는다.

예:1000씩, 내가60·상대100 납부 후내가종료→940/1060. 상대100은 자기돈반환. 내가20만내고체스승리확인뒤포커중종료→980/1020. 이미 확정·저장된 최종정산은 다시 도주처리하지 않는다.

강제종료·브라우저충돌·네트워크상태를 의도로 구별할 수 없다. 웹은 미완료 판 마커를 먼저 저장하고 다음 실행에서 한 번만 도주정산하는 방식. 사용자 손실을 숨기지 않도록 입장 시 ‘이 판을 끝내기 전에 나가면 납부한 판돈을 잃습니다’ 명시. 탭 숨김만으로는 즉시 패배시키지 않는다. 새로고침도 미완료 세션 종료와 같다는 정책은 확인할 미결사항이다.
