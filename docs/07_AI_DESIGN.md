# 07 · 내장 컴퓨터 상대

## 실행 방식

상대는 생성형 AI 서비스가 아니라 TypeScript로 작성한 로컬 탐색 로직이다. API 키나 외부 추론 호출을 사용하지 않는다. 체스 계산은 초기 번들에 포함되어 추가 Worker 다운로드 없이 실행된다. 포커 최적 조합 탐색은 약 12ms 단위로 브라우저에 제어를 돌려주며, 판/단계 변경 시 취소한다.

## 체스 선택

합법 후보 각각을 둔 뒤 상대의 합법 응수를 한 수 살펴보는 2-ply 방식이다. 체크메이트, 6→5 캡처와 체크 특례를 우선 점수화한다. 일반 기물 가치와 캐슬링, 중앙 이동, 자기 카드의 랭크·페어 가능성·같은 무늬·연결 랭크·조커 보존을 고려한다. 약간의 난수로 같은 판 반복을 줄인다. 목표는 3/10 초급이며 강한 체스 엔진이나 Elo 보장으로 표현하지 않는다.

## 정보 경계

`aiView`는 공개 FEN, 상대 색, 상대가 소유한 카드 매핑만 생성한다. 플레이어의 숨은 카드 매핑을 전달하지 않는다. 상대 카드 정체성을 섞어도 이 입력이 변하지 않는 회귀 테스트가 있다. 기물의 역할과 위치는 공개 정보다.

## 포커

생존 카드 중 모든 5장 후보를 합법 조커 치환과 함께 평가하여 최적 패를 고른다. 베팅은 자기 패 등급, 공개 투입액·잔액, 콜 부담, 마지막 레이즈 폭, 행동 가능 여부, 난수만 사용한다. 약한 패로 큰 콜 부담을 만나면 폴드하고, 강한 패나 일부 약한 패로 베트/레이즈한다. 정밀 상대 모델링은 없다.

## 오류와 검증

컴퓨터 수 계산은 입력 스냅샷에서 다음 상태를 만든 후 동일 판·동일 수순 길이일 때만 반영한다. 메뉴를 열면 대기 중 체스·베팅 행동을 취소한다. 부정 입력의 실제 예외는 표시하되, Worker 로딩 실패가 정상 게임을 막는 경로는 제거했다. 네트워크와 Worker가 없는 환경에서 첫 수에 응수하는 테스트를 수행했다.
